使用 GitHub Copilot 寫程式、請 AI 解釋錯誤或協助修補專案時，如果常用模型在選單裡不見了，先別急著以為帳號故障。GitHub 早在 2026 年 9 月 18 日就公告，六款模型預定於 10 月 19 日 從 Copilot 的相關體驗中退役，包括 Chat、程式碼補全和 Agent 等模式。

為什麼台灣使用者也值得注意？

首先，模型退役是 GitHub Copilot 產品的變更，不能直接推論 ChatGPT、Gemini、Grok 各自官網或 API 在同一天也停用相同模型。其次，習慣在團隊流程、Agent 規則或 IDE 中指定特定模型的人，應檢查工作流程有沒有依賴舊選項。即使 Copilot 能提供新模型，也不代表舊設定能在每一種環境下自動遷移。

三步確認，不必先花錢

第一步： 開啟自己使用的 GitHub Copilot（網站、支援的 IDE 或 CLI），查看模型選單與當前方案。找不到模型前，先檢查擴充套件與登入狀態；不要直接推論平台全面故障。

第二步： 把正在使用的舊模型名稱與上表比對。個人使用者可檢查實際提供的替代模型；Business／Enterprise 組織使用者應由管理員檢查 Copilot model policies。GitHub 說明，若沿用預設模型啟用政策，建議替代模型通常會自動開放；若管理員停用全域預設或個別模型，可能仍需手動設定。

第三步： 用不含機密資料的相同測試題比較更換前後的輸出品質。例如請 AI 解釋一小段公開範例程式、列出風險與修改建議，再人工確認差異。尚未實際測試之前，不應聲稱任何替代模型「更快」或「更準」。

常見問題

Q：GPT-5.5 停用代表 ChatGPT 也不能用了嗎？

A：本篇引用的是 GitHub Copilot 公告，不能據此推論其他獨立產品或 API 的供應狀況。

Q：一定要換到較貴方案嗎？

A：本次公告沒有提供「每位使用者一定要升級付款」的結論。先依自己的 Copilot 方案、管理員政策與模型選擇權限確認，本文不列未再核實的台幣或美元價格。

Q：免費版 Copilot 使用者要做什麼？

A：先看帳號中是否有可使用的模型或自動選模選項；不要假設免費方案必然支援上表所有替代模型。實際方案差異以 GitHub 官方文件為準。

編輯觀點：選模型前，先想工作和風險

對一般工作者而言，「今天最強」未必是最佳選擇。衡量 AI 工具時，與其只認模型名稱，更應評估工作用途、結果是否可驗證、資料是否敏感、費用或額度限制，以及能否順利更換工具。尤其是會修改程式碼、存取倉庫或自動執行任務的 AI，仍需保留人工審查與最小權限。
